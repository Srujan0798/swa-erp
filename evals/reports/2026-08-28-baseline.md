## What each eval actually exercised (real contract, not "looks right")

- **001** Inquiry→Client, ambiguous-match branch: POST inquiry → POST convert (no
  client_id) returns **300** with `candidates` → POST convert (client_id=candidates[0])
  returns **200**, inquiry.status=`Converted`, `converted_client_id` equals the picked
  existing client (reused, not re-created), project.code=`APC-001`.
  *Note:* in the reuse branch the existing client keeps its own `code`; the
  `SWA-{year}-CLT-{seq:03d}` format is only minted in the new-client branch. The grader
  asserts reuse, not SWA-format, on the reused client.
- **002** ID chain: inquiry→agreement→token→docref all get `SWA-{year}-{TYPE}-{seq:03d}`
  refs, sequences monotonic within the year, and FKs wire up (agreement.client_id,
  token.agreement_id, docref.token_id, docref.project_id).
- **003** RBAC: Viewer GET /api/projects → **200**; Viewer POST /api/clients → **403**
  (exact); Viewer PATCH /api/projects/{id} → **403** (exact); no `HACK-001` client
  persisted; project name unchanged.
- **004** Time→dashboard: 7 billable + 1 non-billable hour → timesheet totals 8h / 7
  billable, status `draft`; invoice generated from time = 35000 + 18% GST = **41300.00**,
  DB money stays `Decimal`.
- **005** Invoice GST: 2000+750+200 = 2950 subtotal; 18% GST = **531.00**; total =
  **3481.00**; subtotal+gst == total (no rounding gap); DB money fields are `Decimal`,
  not float; per-line amounts exact.

## Bugs found while building the evals (and how they were handled)

None in application code. The failures encountered during harness development were
**harness/eval bugs**, not system bugs:

1. `reset_db` initially truncated via a *separate* engine connection → deadlocked on the
   app's idle-in-transaction connection (suite crawled for 10 min). Fixed by truncating
   on the *same* `db_session` the app is bound to.
2. Grader 005 originally asserted money fields serialize as JSON `str` — false; the API
   returns `Decimal` (JSON number). Corrected to assert DB-layer `Decimal(18,2)` and
   numeric equality.
3. Grader 001 originally asserted `SWA-…` format on the reused client — false for the
   ambiguous-reuse branch. Corrected to assert reuse (id match) + project code.
4. ctx envelope shape (graders expect `response_body` / `result`) was reconciled with the
   harness so the two agree — the graders are now the contract, the harness feeds them.

Per the task constraints, **zero application-code changes** were made. Evals revealed the
*contract* assumptions in the scaffold's graders were wrong; those grader bugs were fixed
in `evals/graders/code_based.py` (an eval file, not app code), and reported here.

## Honesty note

This is a **baseline**, not a certification. 5 client workflows pass deterministically
today. The eval set is small and hand-authored; it is not a substitute for ongoing
monitoring. The evals CI job is intentionally non-blocking (see `evals/README.md`
"Anti-patterns" and the workflow header) so nobody mistakes a green evals check for a
real merge gate.
