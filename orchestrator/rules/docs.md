# Documentation rules

- Every public API endpoint documented in `docs/api.md` (or auto-generated from OpenAPI)
- Every major decision → ADR in `docs/decisions/`
- README always reflects current state (no stale "coming soon")
- HOW_TO_RUN.md always reflects current dev/deploy setup
- HIERARCHY.md updated when folder structure changes
- CHANGELOG.md bumped on every wave ship
- Inline code comments: explain WHY, not WHAT
- Module docstrings: 1 paragraph, what it does + key invariants
- No documentation as decoration — every doc must answer a question someone will actually ask
