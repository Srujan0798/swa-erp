## Findings

### CRITICAL (must fix before next wave)
- **(none) ✅** — Wave-37 critical hardening is present in code:
  - Path traversal contained: `src/backend/core/storage.py:46-48,60-65` (`relative_to(root)`
    guard; absolute keys rejected).
  - Insecure secret denylist expanded and enforced in non-dev: `src/backend/core/config.py:5-11,44`.

### HIGH (fix in next wave)
- **H-1 — JWT refresh tokens not rotated on use.** A stolen refresh token is reusable up to
  `JWT_REFRESH_TTL_DAYS = 30`. Logout revokes the refresh *row*, not the presented token. Today's
  only full mitigation is `SECRET_KEY` rotation (logs everyone out). Source review
  `work/reports/wave-37/_findings-security.md` SEC-06. **Decision needed:** schedule token
  rotation/denylist work.
- **H-2 — `/metrics` exposure posture must stay internal.** Verified: `/metrics` now requires
  authentication (`src/backend/main.py:113-114`, `get_current_user` dependency) — an improvement
  over the earlier unauthenticated exposure. Operator must still never publish port 8000 publicly.
  Recorded as satisfied-but-watch.

### MEDIUM (backlog)
- **M-1 — Performance budget not yet enforced in CI.** `perf_regression.yml` did not exist at audit
  time; it is being added in this wave and must fail builds past the SLO floor
  (`docs/operational/PERFORMANCE_SLOS.md`).
- **M-2 — Time-tracking IDOR reads** (any authenticated user can read others' hours).
  `work/reports/wave-37/_findings-security.md` SEC-04. Writes are owner-scoped; reads are not.
- **M-3 — Financial RBAC inconsistency** (some P&L cost reads auth-only vs `PM+` for exports).
  SEC-05.
- **M-4 — Client production server never load-tested.** Capacity promise deferred until a run on
  the Windows Server. `docs/PERFORMANCE.md:254-269`.

### LOW (informational)
- **L-1 — Operational docs now complete** for T2: `docs/operational/` contains OBSERVABILITY,
  PERFORMANCE_SLOS, INCIDENT_RESPONSE_PLAYBOOK, PRODUCTION_WALKTHROUGH, SECURITY_PERIMETER_GUIDE,
  DATA_INTAKE_PROTOCOL (all present at audit time).
- **L-2 — Sentry PII scrubbing confirmed in code** (`src/backend/core/errors.py:23,40,71`
  redacts auth headers, password/secret/token/PII keys before send; no-op when `SENTRY_DSN` unset).
- **L-3 — Health surface verified:** `/healthz` (liveness, `health.py:13-16`) and `/readyz`
  (db+redis+migrations, `health.py:19-82`). Note `/readyz` 503s without Redis — expected, see
  PRODUCTION_WALKTHROUGH / INCIDENT_RESPONSE_PLAYBOOK §2.
