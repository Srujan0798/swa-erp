# Report — Wave 13 · 01 Excel → ERP data migration importer

## Result
**DONE** — acceptance checks pass. (Unblocked after wave-9 models landed.)

## What was built
- `scripts/import_excel.py` — CLI with subcommands `clients, inquiries, agreements, tokens,
  document_references, projects, time_logs, sustainability`; `--dry-run` default, `--commit` for
  writes; prints a JSON summary `{sheet_type, total_rows, created, updated, skipped, errors, ok}`;
  exits non-zero when `errors` is non-empty.
- `src/backend/services/import_service.py` — sheet parsing (robust header-row detection that skips
  the metadata/duplicate-header rows and key-less junk rows seen in the real dumps), per-sheet
  validation, idempotent upsert on natural keys (`Client.code`, `Inquiry.reference_id`,
  `ServiceAgreement.reference_id`, `Token.reference_id`, `DocumentReference.reference_id`,
  `Project.code`), and FK resolution with clear "referenced X not found" messages.
- `tests/wave-13/test_import_service.py` + `tests/wave-13/fixtures/*.xlsx` (synthetic, **no real PII**)
  generated by `tests/wave-13/generate_fixtures.py`; a deliberately malformed row exercises the
  error reporter. Tests run on isolated SQLite (no postgres dependency).
- `Makefile` target `make import-data file=<path.xlsx> type=<sheet> [commit=1]` (default dry-run).
- `openpyxl` already present in `requirements.txt`.

## Special handling implemented
- `Client.First Lead ID` (`LDI-*`) stored as `first_lead_id`; `First Inquiry ID` resolved against
  `Inquiry.reference_id` → `first_inquiry_id`.
- `Document Reference Sheet` dual headers (`Associated Project/Token ID`): resolved as a Project code
  first, else a Token reference; `project_id` is required, `token_id` set when a token resolves.
- `Time Logging` polymorphic `Reference ID` resolved Project → Token → DocumentReference; `user_id`
  satisfied via a seeded `import@swa.local` user (no real user rows needed).
- `Employees` HR-sensitive columns are not mapped to any model field.

## Wave-9 dependency note
The blocker reported earlier (missing `Token` / `DocumentReference`) cleared when wave-9 landed.
The merged `Token` model uses `token_date` (required), `swa_employee_id` / `project_owner_id`
(FK → users, optional, name-resolved), `client_employee_name`, and keeps `project_id` optional.
The merged `DocumentReference` model uses `reference_id` (not `drn`), `doc_date`, `type_`,
`author_id`, `user_ref`, `revision`, `status`, `remarks` — the importer was aligned to exactly
this schema. `models/__init__.py` now exports both.

> Caveat: the dev **postgres** DB (`swa_erp`) had not been migrated to wave-9 at run time
> (`service_agreements.reference_id does not exist`), so the raw `scripts/import_excel.py ...`
> command against the default DB reports an FK-resolution error. This is a migration gap, not an
> importer bug — `make migrate-up` (or `alembic upgrade head`) on the target DB resolves it. The
> importer is verified against a correctly-migrated schema via the SQLite test suite and a
> seeded-sqlite CLI run (`created: 1, ok: true`).
